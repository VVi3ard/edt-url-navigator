# EDT URL Navigator: правки по итогам проверки (2026-10-18)

Плагин `com.github.vvi3ard.dt.navigator` 1.0.0.v20261018164431, EDT 2026.2, воркспейс `C:\EDT\isssues\_ASPU_Master\work`.
Лог для проверки: `C:\EDT\isssues\_ASPU_Master\work\.metadata\.log` (записи `com.github.vvi3ard.dt.navigator`).

Что уже работает (не сломать): `module` + `line` / `method`, `МодульОбъекта`, `МодульМенеджера`, `Форма.X`, `МодульСеанса`, `project=`, `file=` (относительно `src/` и относительно корня репозитория).

## 1. `md=` / `md=…&attr=…` открывает Explorer вместо редактора EDT (баг, главное)

Симптом: `/open?md=Документ.ЗаявкаНаВнесениеВзносов&attr=НомерЗаявления` → открывается проводник Windows на папке `…\src\Documents\ЗаявкаНаВнесениеВзносов`; в EDT ничего не открывается, ошибок в логе нет.

Причина (вероятная): `ModuleNavigator` открывает `.mdo` через `IDE.openEditor(page, file)` — редактор по умолчанию для расширения. Для `.mdo` в Eclipse его нет → берётся внешний системный редактор → у `.mdo` нет ассоциации в Windows (`assoc .mdo` → not found) → Explorer. Позиционирование `selectAndReveal` при этом невозможно: это не `ITextEditor`.

Исправить:
- Объект метаданных (`md` без `attr`) открывать в штатном редакторе объекта EDT (через EDT API по объекту метаданных, а не по файлу).
- С `attr` — либо выделять реквизит в редакторе объекта EDT, либо открывать `.mdo` явным текстовым/XML-редактором (`IDE.openEditor(page, file, "org.eclipse.ui.DefaultTextEditor")` или XML-редактор, если есть) и делать `selectAndReveal` на `<name>attr</name>`.
- Никогда не отдавать файл внешнему системному редактору: если подходящего редактора нет — писать ошибку в лог.

Готово, когда: `md=Документ.X` открывает объект в EDT; `md=Документ.X&attr=Y` показывает реквизит Y; `md=Конфигурация` открывает конфигурацию; Explorer не открывается ни в одном случае.

## 2. HTTP-шлюз оставляет вкладку браузера с JSON

Контекст: в приложении Claude (desktop) ссылки `edt://` не кликаются, поэтому LLM даёт ссылки `http://127.0.0.1:18321/open?…`. Каждый клик открывает вкладку браузера с `{"status":"ok",…}`.

Исправить: на `GET /open` из браузера (`Accept` содержит `text/html`) отвечать `text/html`: короткий статус («Открыто в EDT» / текст ошибки) и `<script>window.close()</script>`; если браузер не дал закрыть — оставить страницу со статусом. JSON сохранить для `Accept: application/json` и `POST`.

Готово, когда: клик по http-ссылке из приложения Claude открывает объект в EDT, вкладка закрывается сама (или показывает понятный статус, а не JSON).

## 3. `/open` отвечает `ok` даже когда объект не найден

Симптом: `/open?module=ОбщийМодуль.НетТакогоМодуля` → `{"status":"ok","message":"Navigation dispatched"}`, а в логе потом `Could not resolve file for target`. Так же для `project=ASPU.ТПМ`, если там нет модуля.

Исправить: разрешать файл (`resolveFile`) синхронно до диспетчеризации в UI-поток; при неудаче — `404` с причиной (JSON и HTML из п. 2). Открытие редактора и позиционирование могут оставаться асинхронными.

Готово, когда: несуществующий модуль / объект / неверный `project` → 404 с причиной; существующий → 200.

## 4. Документация расходится с кодом

- `search=` описан в `LLM-LINKS-GUIDELINE.md`, но не разбирается (его нет в `NavigationTarget`). Либо реализовать, либо убрать из документации.
- `path=` есть в `NavigationTarget`, но нигде не описан. Описать (что принимает) или убрать.
- `LLM-SETUP-PROMPT.md` (промпт для LLM) не менять без необходимости; если меняется набор параметров — обновить и его.
